# 开源脱敏流程

## 1. 隔离原始材料

生产备份只进入本地隔离目录。不得在隔离目录初始化 Git，也不得把隔离目录作为发布目录的上级目录。

## 2. 白名单重建

公开仓库应从空目录创建，只添加必要源码、配置模板、文档和合成数据。不要采用“复制全部再删除敏感文件”的流程。

## 3. 替换数据

- 人员：使用角色化名称和 `demo_` 前缀标识
- 组织：使用“示例一厂”“示例安全组”等虚构名称
- 时间：使用明显的演示年份或动态生成
- 地址：使用描述性区域，不使用真实园区、经纬度或门牌
- 附件：使用空白占位图或自行创作的通用素材

## 4. 配置外置

所有密钥、域名、回调地址、群 ID 和用户映射均由环境变量或密钥管理服务注入。`.env.example` 只能含占位符。

## 5. 多轮检查

1. 文件类型和目录黑名单
2. 凭证、私钥、Token、内网 IP、手机号、邮箱和身份证候选格式扫描
3. Git 历史扫描
4. 演示数据人工抽检
5. 新克隆仓库安装、测试和构建
6. 发布前由与开发者不同的人复核

## 6. 发现问题后的处理

如果敏感信息已经进入 Git 历史，应立即停止发布，吊销相关凭证，清理完整历史并重新扫描。只删除当前版本文件不能消除历史泄露。
